# Seclaria

> Rustで構築された、安全かつクロスプラットフォームなAIエージェント・ハーネス。マルチプロバイダLLM、権限ゲート付きツール、リッチTUI、多層サンドボックスを備えます。

Seclariaは、Rustで開発する汎用AIエージェント・ハーネスです。

Claude Codeのようなエージェント実行体験を提供しつつ、ツール実行を明示的な権限境界と多層サンドボックスの内側へ閉じ込めることを目指しています。

モデルプロバイダ、ツール、実行ポリシー、サンドボックス、フロントエンドを分離し、それぞれを独立して拡張できる構成を採用します。

> [!IMPORTANT]
> Seclariaは現在、設計および初期実装段階です。  
> このREADMEにはプロジェクトの構想と目標アーキテクチャを含みます。記載しているすべての機能が実装済みとは限りません。

---

## プロジェクトの目的

Seclariaは、次の機能を備えた汎用エージェント基盤を目指します。

- プロバイダに依存しないエージェントランタイム
- Claude Codeに類似したツール呼び出し型ワークフロー
- 副作用の発生前に必ず通過する権限ゲート
- ファイル、プロセス、ネットワークに対する多層隔離
- 対話モードと非対話モードの両立
- Windows 11を含むクロスプラットフォーム対応
- 監査可能で再現性のあるエージェント実行
- 長期的な拡張に耐えられるRustワークスペース構成

基本原則は明快です。

> モデルは操作を提案できますが、実際に何を許可するかはSeclariaが決定します。

## 主な機能

### マルチプロバイダLLM

Seclariaは、エージェントエンジンが特定のAPI形式へ依存しないよう、正規化されたプロバイダ抽象を採用します。

対応予定のプロバイダは次のとおりです。

- OpenAI Chat Completions API
- OpenAI Responses API
- OpenAI互換エンドポイント
- LM Studio
- Anthropic Messages API
- 決定的なテストに使用するMockプロバイダ

プロバイダごとに異なる以下の要素は、エンジンへ渡す前に共通形式へ正規化します。

- ストリーミングイベント
- ツール呼び出し形式
- 構造化出力
- Usage情報
- エラー分類
- ThinkingやReasoningブロック
- キャッシュ情報

### エージェント・ツールループ

ランタイムは、次のツール呼び出しループを管理します。

1. 会話状態からプロバイダ非依存のリクエストを構築する
2. モデルの応答をストリーミング受信し、共通イベントへ正規化する
3. モデルが提案したツール呼び出しを収集する
4. 各ツール呼び出しをパーミッションシステムで評価する
5. 許可されたツールだけを実行する
6. ツール結果を共通形式でモデルへ返す
7. ターンが完了するまで処理を継続する

組み込みツールとして、次の機能を予定しています。

- `read_file`
- `write_file`
- `edit_file`
- `run_shell`
- `grep`
- `glob`
- `web_fetch`

### 権限ゲート付きツール実行

すべてのツール呼び出しは、実行前に中央集約されたパーミッション判定を通過します。

想定しているパーミッションモードは次のとおりです。

- **Plan**  
  読み取り専用です。書き込み、コマンド実行、ネットワーク操作を拒否します。

- **Default**  
  読み取りは自動許可し、書き込み、コマンド実行、ネットワーク操作は承認を要求します。

- **AcceptEdits**  
  ファイル編集を自動許可し、シェル実行とネットワーク操作は引き続き承認対象とします。

- **AcceptAll**  
  明示的に有効化した場合のみ、すべての操作を許可します。

- **Deny**  
  すべてのツール呼び出しを拒否します。

許可ルールは、ツール名と具体的な入力へ制限できます。

```text
run_shell:cargo test
run_shell:git status
write_file:src/**
web_fetch:*.rust-lang.org
```

パーミッション層は、TUIとヘッドレスモードの両方で共通です。

フロントエンドごとに異なる実行経路を持たせず、中央の強制点を迂回できない構造を目指します。

### 多層サンドボックス

Seclariaでは、サンドボックスを単一機能ではなく、複数の保証を組み合わせた防御層として扱います。

目標設計には、次の要素を含みます。

- Capabilityベースのワークスペースアクセス
- パス、シンボリックリンク、reparse pointの検査
- 読み取り・書き込みスコープ
- 秘密情報を含む環境変数の除去
- ステージングされたファイル変更
- 子プロセスの隔離
- ネットワーク出口制御
- タイムアウト、出力上限、リソース上限
- 監査ログ
- VMレベルの隔離

シェル実行は、ホスト環境で利用できる保証に応じてTierへ分類します。

| Tier | 想定する隔離方式 |
|---|---|
| **Tier 3** | Hyper-V VMとIncusコンテナによる隔離 |
| **Tier 2b** | Linux namespace、Bubblewrap、OverlayFS、Landlock、ネットワーク制限 |
| **Tier 2a** | Windows AppContainer、明示ACL、Capabilityによるネットワーク制御 |
| **Tier 1** | Restricted Token、Low Integrity、Job Object |
| **Tier 0** | ツール側制限のみを用いるベストエフォート実行 |

要求した隔離レベルを利用できない場合は、明示的に降格を通知します。

厳格なサンドボックスが必要な実行では、弱いTierへ降格せず処理を拒否できる設計とします。

### ファイルのステージングとレビュー

ファイルサンドボックスでは、複数の書き込みモードを想定しています。

- **Live**  
  ワークスペースへ直接書き込みます。

- **Workspace Commit**  
  ワークスペース内の変更をステージングし、後からまとめてレビューして適用します。

- **Staged**  
  明示的に適用するまで、すべての変更を実ファイルシステムの外側へ保持します。

- **Copy-on-Write**  
  対応する子プロセスの書き込みを上位レイヤーへリダイレクトし、レビュー可能な変更として扱います。

ステージングされた操作はマニフェストへ記録し、ユーザーが変更単位で確認、許可、拒否、適用できるようにします。

### リッチTUI

非同期イベントストリームを利用したTUIを実装予定です。

TUIでは、次の情報を表示します。

- アシスタント応答のストリーミング表示
- プロバイダが対応する場合のThinking・Reasoningブロック
- ツール呼び出しカード
- パーミッション承認ダイアログ
- コマンド出力と終了コード
- ステージングされたファイル変更
- トークン使用量とプロバイダ状態
- サンドボックスTierと実行ポリシー

TUIとヘッドレスモードは、同じエンジンと同じセキュリティ境界を利用します。

### ヘッドレス・CI実行

Seclariaは、非対話環境での利用も想定しています。

```bash
seclaria -p "テストスイートを実行して失敗原因を要約してください"
```

出力形式として、次を予定しています。

```text
text
json
jsonl
```

ヘッドレスモードでは、対話的な承認要求を暗黙に許可しません。

選択されたパーミッションモードと事前定義ルールによって許可された操作だけを実行し、CI上での動作を決定的かつ監査可能にします。

## アーキテクチャ

Seclariaは、責務を明確に分離したCargo workspaceとして構成します。

```text
seclaria-core
├── 会話IRと共通イベント型
├── Provider・Tool trait
└── 共通エラー型とUsage情報

seclaria-config
├── 階層設定
├── プロバイダプロファイル
└── パーミッションルール

seclaria-providers
├── OpenAI
├── OpenAI互換 / LM Studio
├── Anthropic
└── Mockプロバイダ

seclaria-tools
├── 組み込みツール
├── ToolRegistry
└── JSON Schema生成

seclaria-sandbox
├── ワークスペースjail
├── ステージングとオーバーレイ
├── シェル隔離Tier
└── 読み取り・書き込み・プロセス・ネットワークポリシー

seclaria-engine
├── ConversationState
├── エージェントループ
├── Permission Arbiter
└── ツールディスパッチ

seclaria-tui
└── 対話型ターミナルフロントエンド

seclaria-cli
└── CLI・ヘッドレス実行エントリポイント
```

拡張可能な境界は、主に次の2つです。

- `LlmProvider`
- `Tool`

プロバイダとツールはtrait objectを通じて拡張可能にします。

一方、会話ブロック、ストリームイベント、停止理由、エージェントイベントなどの共通語彙はenumで表現し、コンパイラによる網羅性検査を利用します。

## セキュリティ方針

Seclariaは、生成されたコマンドや取得されたコードが信頼できない可能性を前提とします。

そのため、次の原則に基づいて設計します。

### 1. 既定拒否

権限は暗黙に推測せず、明示的に宣言された範囲だけを許可します。

### 2. 強制点の中央集約

ツール実行、パーミッション判定、サンドボックス判定は、共通の強制点を必ず通過させます。

### 3. 意図と権限の分離

モデルが操作を要求したことは、その操作を実行する権限があることを意味しません。

### 4. OS境界の優先

アプリケーション層のパス検査だけでは、任意の子プロセスを完全には制限できません。

可能な限り、OSやVMが提供する強制アクセス制御を利用します。

### 5. 降格の可視化

弱い隔離へ切り替わった場合、それを同等のセキュリティとして扱わず、ユーザーへ明示します。

### 6. 監査可能性

すべての許可・拒否判断について、どのルールによって決定されたかを記録できるようにします。

### 7. 実行前の秘密情報保護

子プロセスへ不要な秘密環境変数を継承させません。

ツール出力についても、プロバイダ送信やログ保存の前に秘密情報のマスキングを行います。

### 8. ネットワークをCapabilityとして扱う

組み込みHTTPツールだけでなく、子プロセスによる直接通信や迂回経路も別々に考慮します。

## 対応プラットフォーム

主な対象は次のとおりです。

- Windows 11
- Linux
- macOS

Windowsは補助的な対応ではなく、主要プラットフォームとして設計します。

具体的には、次のWindows固有要素を考慮します。

- PowerShell 7

- AppContainer
- Restricted Token
- Integrity Level
- Job Object
- Windows Filtering Platform
- Hyper-V
- ADS
- UNCパス
- 予約デバイス名
- Reparse Point
- Windows固有のパス正規化

利用可能なサンドボックスTierは、OSとホスト環境によって異なります。

## 設定例

設定形式は現在検討中ですが、ユーザー設定、プロジェクト設定、CLI引数を階層的にマージする構成を想定しています。

```json
{
  "provider": {
    "default": "local"
  },
  "providers": {
    "local": {
      "kind": "openai-compatible",
      "base_url": "http://127.0.0.1:1234/v1",
      "model": "local-model"
    }
  },
  "permissions": {
    "mode": "default",
    "allow": [
      "run_shell:git status",
      "run_shell:cargo test",
      "write_file:src/**"
    ]
  },
  "sandbox": {
    "require": true,
    "network": "deny-by-default"
  }
}
```

この例は設計意図を示すためのものであり、初回安定版までに変更される可能性があります。

## 非目標

Seclariaは、次のものを目指してはいません。

- 任意の生成コードが安全であることの保証
- すべての脅威モデルにおけるVMの完全な代替
- Tier 0をセキュリティ境界として扱うこと
- 特定プロバイダ専用SDK
- ツールへ広範なホストアクセスを暗黙に与えること
- すべてのOSで完全に同一の挙動を保証すること

プラットフォームの制約を隠すのではなく、各Tierが提供する保証と限界を明示し、組み合わせ可能にすることを目指します。

## Seclariaという名前について

**Seclaria**は、複数の語と設計思想を重ねた造語です。

- **Secure / Security**  
  実行を既定で安全側に制御することを表します。

- **Seclude**  
  エージェントとツール実行をホスト環境から隔離することを表します。

- **Clavis**  
  ラテン語で「鍵」を意味し、権限、Capability、アクセス制御を象徴します。

- **Claustrum**
  「閉ざされた場所」「囲われた空間」を意味する語に由来します。  
  `claustrum`は、脳の構造である「前障」を指す医学・解剖学用語でもあります。

この名前には、次の設計思想を込めています。

> LLMを人工的な脳として捉え、その行動を制御された実行領域へ閉じ込め、明示的な鍵と権限を通じてのみ外部への作用を許可する。

Seclariaは、単にLLMへ文章を生成させるためのクライアントではありません。
エージェントにツールを与えながらも、ファイル、プロセス、ネットワーク、副作用、権限を明示的に管理するための実行基盤を目指します。
